You are continuing the Sweet Smile interactive 3D ice-cream website/game project.

PROJECT GOAL
Build a premium, warm, cinematic, interactive 3D ice-cream product-builder experience for the Sweet Smile brand.
This must feel like a small game, not a normal ecommerce page.

CORE USER EXPERIENCE
The visitor should actually construct an ice cream:
1. Choose Cone or Cup.
2. Choose up to 3 scoops.
3. Choose toppings.
4. The character physically performs the selected action.
5. The selected 3D ingredient visibly moves into the product.
6. The user can remove an ingredient.
7. The user can throw an unwanted item into a visible trash bin.
8. The user can reset and start again.
9. The user can finish the creation and add it to the bag/order.

NON-NEGOTIABLE CHARACTER REQUIREMENT
The female shop assistant is the user's custom character.
She must not be treated as a decorative static image.
She must be a real interactive 3D character in the final production version.

GAME LOGIC
Maintain a single source of truth for the order:
{
  base: "cone" | "cup",
  scoops: [],
  toppings: [],
  price: number
}

Rules:
- maximum 3 scoops
- toppings are optional
- duplicate toppings may be disallowed unless intentionally enabled
- every add/remove action updates the 3D product
- every important action triggers a character animation
- the character should never visually perform an action unrelated to the user's current selection

INTERACTION EXAMPLE
User clicks Pistachio:
1. UI highlights Pistachio.
2. Character reaches for the scoop.
3. Character grabs/scoops pistachio.
4. Pistachio scoop object follows the hand.
5. Character moves the scoop over the cone/cup.
6. Scoop is placed.
7. The final scoop remains attached to the ice cream.
8. Character returns to idle.

REMOVE EXAMPLE
User clicks an existing scoop:
1. Selected scoop highlights.
2. Character removes it or performs a discard action.
3. The scoop leaves the product.
4. It can move toward the trash bin.
5. State updates.

TRASH EXAMPLE
If the user chooses to discard:
1. Character picks up the selected object.
2. Character carries it toward the trash.
3. Object falls into the bin.
4. State updates.
5. Character returns to idle.

VISUAL DIRECTION
Warm premium minimal.
Editorial + playful + cinematic.
Avoid childish cartoon styling.
Avoid generic SaaS styling.
Use depth, soft shadows, subtle glass/metal details, warm cream materials, restrained gold accents and olive/berry accents where appropriate.

TYPOGRAPHY DIRECTION
Cormorant Garamond for editorial display headings.
Inter or Neue Montreal style for interface text.
Do not overuse decorative typography.

RESPONSIVE REQUIREMENT
Desktop and mobile must both work.
On mobile:
- builder controls should remain easy to tap
- 3D scene should remain the visual focus
- camera controls must be simple
- no tiny buttons
- no horizontal overflow

PERFORMANCE REQUIREMENT
Target a smooth browser experience.
Use:
- optimized GLB
- compressed textures
- reasonable polygon counts
- lazy loading for heavy assets
- mobile-friendly shadows
- limited real-time lights
- avoid unnecessary post-processing

TECHNICAL DIRECTION
The current prototype uses HTML/CSS/JavaScript + Three.js.
Continue with this architecture unless there is a strong technical reason to migrate.

Keep the game logic independent from WordPress.
The final interactive builder should be embeddable inside a WordPress page/section later.

WORDPRESS INTEGRATION
Do NOT rebuild the whole game inside Elementor.
Build the interactive game as an independent web module first.
Then integrate it into WordPress using the cleanest production method available, such as:
- a custom plugin/module
- iframe only if technically necessary
- or a dedicated front-end bundle embedded into a WordPress template

The final WordPress site should still be maintainable.
